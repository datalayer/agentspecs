# Memory Specifications

Memory specs define selectable memory backends for agents.

## Required Fields

- `id`
- `version`
- `name`
- `description`

## Typical Fields

- `enabled`
- backend-specific configuration fields
- `tags`

## Notes

- Use memory IDs in agent `memory` fields.
- Keep backend selection explicit and versioned in catalogs.

## Mem0 on Datalayer

`memory: mem0` gives an agent memories that outlive its runtime.

- **Where they are kept.** In PostgreSQL (pgvector), under the user who runs the agent and the agent's own id (its agentspec's `id`). Two users never read each other's memories, and two agents of one user each keep their own.
- **Pausing and resuming.** Pausing an agent stops its runtime. Resuming it launches a new runtime for the same agent and user, which reads the same memories back: they never lived on the runtime.
- **What is kept.** What the agent chose to remember, as it said it (its `remember` tool); it reads them back with `search_memory`, and the relevant ones are given to it before each answer.
- **What it needs.** Nothing from you on Datalayer: the memories are embedded through Datalayer's inference service, metered on your account. A local run uses mem0's defaults and your own `OPENAI_API_KEY`.

## AgentCore Memory

`memory: agentcore` keeps an agent's memories in [Amazon Bedrock AgentCore Memory](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/memory.html), in a memory resource of your own AWS account.

- **Which memory.** One you created (with its strategies), named in the agentspec, never created by the agent:

  ```yaml
  memory: agentcore
  memory_config:
    memory_id: my_memory-AbCdEf1234
    region: us-east-1
    # optional: namespaces: ["/facts/{actorId}"]
  ```

  or `AGENT_RUNTIMES_AGENTCORE_MEMORY_ID` and `AWS_REGION` in the environment. With neither, the agent refuses to start and says so.
- **Whose.** The actor is the person who runs the agent (their account id); the session is the agent's id. Each kept turn is an event of that actor in that session.
- **What is searched.** The long-term records AgentCore's strategies extract from the turns (facts, preferences, summaries), in each strategy's namespace with `{actorId}` filled in (and `{sessionId}`, when the namespace names it, to keep an agent's records apart). A namespace without `{actorId}` is refused: its records would be read across people. Extraction takes about a minute after a turn is kept.
- **What it needs.** AWS credentials allowed `bedrock-agentcore:CreateEvent`, `ListEvents`, `DeleteEvent` and `RetrieveMemoryRecords` on the memory, and `bedrock-agentcore-control:GetMemory` when no namespaces are configured.
- **Forgetting.** Forgetting removes the turns (events); the long-term records already extracted stay until AgentCore expires them or you delete them in AWS.
