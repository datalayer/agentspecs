# Environment Variable Specifications

Environment variable specifications define configuration values required by MCP servers and skills.

## Overview

Environment variables provide API keys, authentication tokens, and configuration values to agents. Each specification defines the variable's purpose, where to obtain it, and metadata.

## Required Fields

### `id` (string)
Unique identifier (UPPER_SNAKE_CASE, e.g., `KAGGLE_API_TOKEN`, `GITHUB_TOKEN`, `OPENAI_API_KEY`)

**Important**: Unlike other specs, envvar IDs use UPPER_SNAKE_CASE to match environment variable naming conventions.

### `name` (string)
Display name shown in the UI

### `version` (string)
Spec version (currently `0.0.1`).

### `description` (string)
Purpose and usage description

## Optional Fields

### `registrationUrl` (string)
URL where users can obtain the variable (e.g., API key registration page)
```yaml
registrationUrl: https://www.kaggle.com/settings/account
registrationUrl: https://github.com/settings/tokens
registrationUrl: https://platform.openai.com/api-keys
```

### `egress` (object)
Where the variable is sent, when it is a credential sent in a request header to known hosts: `hosts` (DNS names, never `*`), `header` (the request header that carries it) and `prefix` (what comes before it in the header's value, `""` when nothing does).

A runtime engine whose sandbox may hold no secret (Kagent) reads it: the sandbox is given a placeholder under the variable's name, and the sandbox's egress gateway replaces that header with the person's value for these hosts alone. A variable without `egress` that a program reads in its own process (a skill's script, a local MCP server's environment) cannot be kept out of the sandbox: on such an engine, an agent whose skill or local MCP server requires it is refused in a sentence. A remote MCP server's variable sent in its `headers` is put in at egress the same way, with no `egress` of its own (below).
```yaml
egress:
  hosts:
    - api.github.com
  header: Authorization
  prefix: "Bearer "
```

Declared only for a variable that travels in one request header to fixed hosts: `GITHUB_TOKEN` (the `github` skill, `api.github.com`) and `TAVILY_API_KEY` (Tavily's hosted MCP server, `mcp.tavily.com`). A remote MCP server's own `headers` already say where its variable goes, so its variable needs no `egress`. A key sent in an address or a request's body (`PIXABAY_API_KEY`, in the query string) cannot be put in at egress, and has none.

### `tags` (list of strings)
Categorization tags
```yaml
tags:
  - authentication
  - api-key
  - kaggle
  - data
```

### `icon` (string)
UI icon identifier

### `emoji` (string)
UI emoji identifier

## Complete Example

```yaml
# Copyright (c) 2025-2026 Datalayer, Inc.
# Distributed under the terms of the Modified BSD License.

id: KAGGLE_API_TOKEN
version: 0.0.1
name: Kaggle API Token
description: >
  API token for accessing Kaggle datasets, competitions, notebooks, and models.
  Required for Kaggle MCP server authentication.

registrationUrl: https://www.kaggle.com/settings/account

tags:
  - authentication
  - api-key
  - kaggle
  - data
```

## Environment Variable Hierarchy

```
Environment Variable Specification
├── Basic Info (id, name, description)
├── Registration (registrationUrl)
├── Egress (egress: hosts, header, prefix)
├── Categorization (tags)
└── UI (icon, emoji)
```

## Linking to MCP Servers and Skills

Environment variables are referenced by their ID in MCP server and skill specifications:

### In MCP Server Spec
```yaml
id: kaggle
name: Kaggle MCP Server
# ... other fields ...

envvars:
  - KAGGLE_API_TOKEN:0.0.1

args:
  - "--Authorization"
  - "Bearer ${KAGGLE_API_TOKEN}"
```

### In Skill Spec
```yaml
id: data-analysis
name: Data Analysis Skill
# ... other fields ...

envvars:
  - OPENAI_API_KEY:0.0.1

optional_env_vars:
  - PLOT_DPI
  - CHART_THEME
```

## Available Environment Variables

The following environment variables are defined in `agentspecs/env-vars/`:

- **`KAGGLE_API_TOKEN`** - Kaggle API authentication
- **`GITHUB_TOKEN`** - GitHub authentication for MCP server and skills
- **`TAVILY_API_KEY`** - Tavily search, read by the `tavily` MCP server (the `crawl` skill asks no key)
- **`ALPHAVANTAGE_API_KEY`** - Alpha Vantage financial data
- **`OPENAI_API_KEY`** - OpenAI API access
- **`SLACK_BOT_TOKEN`** - Slack bot authentication
- **`SLACK_TEAM_ID`** - Slack workspace identifier
- **`SLACK_CHANNEL_IDS`** - Slack channel access list
- **`GOOGLE_MAPS_API_KEY`** - Google Maps Platform key for the `google-maps` server (Google bills its project)
- **`BOOKING_AFFILIATE_ID`** - Booking.com partner affiliate id for the `booking-com` server
- **`BOOKING_DEMAND_API_KEY`** - Booking.com partner Demand API key for the `booking-com` server
- **`STRIPE_TEST_AGENT_API_KEY`** - A Stripe agent API key from a sandbox (test mode, never live) for the `stripe` server
- **`UNSPLASH_ACCESS_KEY`**, **`PEXELS_API_KEY`**, **`PIXABAY_API_KEY`**, **`FREEPIK_API_KEY`** - One key per stock image provider for the `image-stock` skill, each optional and one enough
- **`UNSPLASH_TIER`** - `demo` or `production`, the rate limit of the Unsplash application (a setting, optional)
- **`GOOGLE_OAUTH_CLIENT_ID`** - Google Workspace OAuth client ID
- **`GOOGLE_OAUTH_CLIENT_SECRET`** - Google Workspace OAuth secret

## Best Practices

1. **ID Format**: Use UPPER_SNAKE_CASE (`KAGGLE_API_TOKEN`, not `kaggle_token` or `KaggleToken`)
2. **Naming**: Follow standard environment variable conventions
3. **Description**: Explain what the variable is used for and which services require it
4. **Registration URL**: Always provide when applicable to help users obtain the value
5. **Tags**: Include service name, type (api-key, token, secret), and category
6. **Security**: Never include actual values in the specification
7. **Documentation**: Be clear about whether the variable is required or optional
8. **Scope**: Define one variable per specification file
