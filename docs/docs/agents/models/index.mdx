# Model Specifications

Model specifications define the AI models available to agents. Each specification captures the model's identity, provider, required credentials, and whether it is the default model used when no explicit model is configured.

## Overview

Model IDs follow the format `provider:model-name` (e.g., `bedrock:us.anthropic.claude-sonnet-4-5-20250929-v1:0`, `openai:gpt-4.1`). This convention makes it easy to identify both the provider and the specific model variant at a glance.

## Required Fields

### `id` (string)
Unique model identifier in the format `provider:model-name`. This is the value used to reference the model throughout the system.
```yaml
id: "bedrock:us.anthropic.claude-sonnet-4-5-20250929-v1:0"
id: "openai:gpt-4.1"
id: "anthropic:claude-opus-4-20250514"
```

### `version` (string)
Spec version (currently `0.0.1`).

### `name` (string)
Display name shown in the UI.
```yaml
name: Bedrock Claude Sonnet 4.5
name: OpenAI GPT-4.1
```

### `description` (string)
Short description of the model's characteristics and strengths.
```yaml
description: Claude Sonnet 4.5 via AWS Bedrock - balanced performance
description: GPT-4.1 by OpenAI - strong general purpose model
```

### `provider` (string)
The model provider: the id of one of the [model-provider specs](../model-providers/) — `anthropic`, `bedrock`, `azure-openai`, `openai`, `alibaba`, `ollama`, `cloudflare`. A model naming a provider with no spec is refused when the catalogue loads.
```yaml
provider: bedrock
provider: openai
provider: anthropic
provider: azure-openai
provider: cloudflare
```

## Optional Fields

### `provider_url` (string)
The page on the provider's website that describes this model — its model card, its
entry in the provider's model list — so a reader can check what the spec says against
what the provider says today.
```yaml
provider_url: "https://platform.openai.com/docs/models/gpt-4.1"
```

### `default` (boolean)
Whether this model is the system default (default: `false`). Exactly one model should have `default: true`. This model is used when an agent spec does not specify a `model` field, and when no environment override is set.
```yaml
default: true
```

### `capabilities` (list of strings)
What the model can be trusted with, from a closed vocabulary: `chat`, `tools`, `codemode`,
`vision`, `thinking`, `decisions` (a typed-decision model: noul, choice and score questions
answered as probabilities), `decider` (a chat model that may be asked those questions and
made to answer in the same shape). A spec naming another word is refused when the
catalogue loads.

### `billing` (string)
How the provider bills it, when worth telling a person choosing one: `standard` (the
provider's own billing) or `credits` (prepaid credits).

### `route` (string)
For Cloudflare, the endpoint the model is asked at: `workers-ai` (Workers AI's own) or
`ai-gateway` (through the account's gateway). Set on every Cloudflare model, in step with
the id's flavour and the file's name; a model of any other provider carries none.

### `context_window`, `zero_data_retention`, `request_logging`, `pricing`
The tokens a request may carry; whether the model's provider keeps nothing once it has
answered; where the route keeps a log of the request (`none`, `gateway`); the provider's
list price, `{input_usd_per_million, output_usd_per_million}` — both required, never
negative — for a service that meters by it.

Each price is the provider's published one, and its spec says where it was read and when:
for Bedrock, the on-demand price of the US cross-region inference profile its `us.` id names
([AWS](https://aws.amazon.com/bedrock/pricing/)); for Anthropic, OpenAI and Cloudflare,
their own price pages; for Azure OpenAI, the Global Standard deployment's price, which is
OpenAI's list price (as [genai-prices](https://github.com/pydantic/genai-prices) prices Azure).
A model whose price is not published for the way it is reached — Alibaba Model Studio, whose
price depends on the region and the prompt's length; a local Ollama model — carries no `pricing`,
and a service that meters by it records the call as not priced, never as free.

### `aliases` (list of strings)
Older ids the spec answers to, kept when an id has to move so `get_model` and the
`AIModels` enum still serve what a consumer named.

### `required_env_vars` (list of strings)
Environment variables that must be set for the model to be available. The system checks these at runtime to determine model availability.
```yaml
required_env_vars:
  - AWS_ACCESS_KEY_ID
  - AWS_SECRET_ACCESS_KEY
  - AWS_DEFAULT_REGION
```

## Complete Example

```yaml
# Copyright (c) 2025-2026 Datalayer, Inc.
# Distributed under the terms of the Modified BSD License.

# AI Model Specification: Bedrock Claude Sonnet 4.5

id: "bedrock:us.anthropic.claude-sonnet-4-5-20250929-v1:0"
version: 0.0.1
name: Bedrock Claude Sonnet 4.5
description: Claude Sonnet 4.5 via AWS Bedrock - balanced performance
provider: bedrock
default: true

required_env_vars:
  - AWS_ACCESS_KEY_ID
  - AWS_SECRET_ACCESS_KEY
  - AWS_DEFAULT_REGION
```

### Cloudflare: Workers AI and AI Gateway

Cloudflare is two products, and a model's `route` is the endpoint it is asked at — a
product, not a kind of model:

- **`workers-ai`** (`cloudflare-wrk-*.yaml`, ids `cloudflare:wrk/<vendor>/<model>`): Workers
  AI's own endpoint, `api.cloudflare.com/client/v4/accounts/{account}/ai/…`. It serves the
  models Cloudflare hosts under `@cf/…` (the namespace is left out of the id and put back
  by the service that calls it) and the third-party models it fronts (`typesafe/jev`)
  alike. A service may still send a `wrk` chat model through the account's gateway when
  the deployment names one; the spec says where the model lives, the deployment how it is
  reached.
- **`ai-gateway`** (`cloudflare-gtw-*.yaml`, ids `cloudflare:gtw/<vendor>/<model>`): through
  the account's AI Gateway, `gateway.ai.cloudflare.com`, which logs the call, applies
  caching and rate limits, and bills it from the account's prepaid credits.

The flavour is the second segment of the id and the start of the file's name, and the
catalogue refuses a spec whose id, file name and `route` disagree, so a reader tells the
two apart at a glance. Two fields say what a route does with the request:
`zero_data_retention` is the model provider's retention and nothing else, `request_logging`
(`none` or `gateway`) is where the route keeps a log — Jev through the gateway is ZDR at
Typesafe *and* logged at the gateway. A route for sensitive data is chosen on both.

Jev is in the catalogue once per route, `cloudflare:gtw/typesafe/jev`
and `cloudflare:wrk/typesafe/jev`: the same model, asked at
`gateway.ai.cloudflare.com/v1/{account}/{gateway}/workers-ai/run/typesafe/jev` or at
`api.cloudflare.com/client/v4/accounts/{account}/ai/run`. Its capability is `decisions`, not
`chat`: it answers `noul`, `choice` and `score` questions about a state as calibrated
probabilities, through `datalayer-ai-inference`'s `POST /api/ai-inference/v1/decisions`,
and a picker of chat models must leave it out. A chat model with the `decider` capability
(`gpt-oss-120b`, Claude Sonnet 4.6) may be asked the same questions and made to answer in
the same shape, for comparing with Jev on the same cases; its probabilities are what it
says they are.

Every Cloudflare model is hosted through `datalayer-ai-inference`, which holds the account
and token and sends calls through the account's AI Gateway, so `required_env_vars` is
empty; a runtime that calls Cloudflare itself (`inference_provider: local`) needs
`CLOUDFLARE_ACCOUNT_ID` and `CLOUDFLARE_API_TOKEN` (`CLOUDFLARE_GATEWAY`, `default` unless
set).

Two kinds of billing, in `billing`: `standard`, the `@cf/` models on the account's Workers AI
billing, in neurons; `credits`, the frontier ones (GLM, Kimi) and the gateway's third-party
models (Jev) from prepaid AI Gateway credits — which is what makes the frontier models
available without the Workers Paid plan once the gateway's *Workers AI billing* is set to
unified. A spec that a service meters by its list price carries `pricing` (dollars per
million input and output tokens); `context_window` and `zero_data_retention` say the rest.

|-------|----|-------|-------|
| **gpt-oss-120b** | `cloudflare:wrk/openai/gpt-oss-120b` | workers-ai | 128k context, tool calling; a decider |

The catalogue moves: `scripts/check-cloudflare-models.py` in agent-runtimes holds the
`cloudflare-wrk-*` specs to what the account's listing serves, and names the served
models that have tool calling and no spec yet.

## Linking Models to Agents

Agents can specify a model in their YAML spec using the model ID:

```yaml
# In agent spec
model: "bedrock:us.anthropic.claude-sonnet-4-5-20250929-v1:0"
```

If an agent does not specify a `model` field, the system default model (marked with `default: true`) is used.

## Code Generation

Model specifications are used to generate:

- **Python**: `AIModels` enum, `AIModel` dataclass, `AI_MODEL_CATALOGUE`, and `DEFAULT_MODEL` constant
- **TypeScript**: `AIModels` object, `AIModel` interface, `AI_MODEL_CATALOGUE`, and `DEFAULT_MODEL` export

Run `make specs` in the agent-runtimes repository to regenerate from the YAML files.

## Best Practices

1. **ID Format**: Use the `provider:model-name` convention
2. **Single Default**: Ensure exactly one model has `default: true`
3. **Environment Variables**: Always list all required credentials in `required_env_vars`
4. **Descriptions**: Keep descriptions short — mention the provider, model tier, and key characteristic
5. **Provider Consistency**: Use the canonical provider names (`anthropic`, `bedrock`, `azure-openai`, `openai`)
6. **File Naming**: Use kebab-case matching the provider and model name (e.g., `bedrock-claude-sonnet-4-5.yaml`)
