# Guards

A Guard is a reusable verification and protection component: it checks whether
the output or the action of a Cog or an Op is correct, safe, policy-compliant
and ready for use. Guards check; [Gates](../gates) decide. The idea, and the
word, are those of the [Intelligence Hub whitepaper](https://github.com/openteams-ai/inthub-whitepaper/blob/main/whitepaper.md) (section 5.1).

## A Guard extends a Policy

A [Policy](../policies) is the Shield's document: the rules that decide what
may be read, written, deleted, executed, sent and bought, the limits, the hosts
and the MCP servers lent. It bounds what an agent may do — and nothing in it
verifies that the bounds held. A Guard is that verification.

`extends` names the Policy, `id` or `id:version`, from the policies catalogue;
a Guard naming a Policy the catalogue does not hold is refused as it is read.
The Policy is not merged into the Guard: the resolved Guard carries `policy`,
the Policy's `id:version`, and `policy_of` gives the Policy — the standard the
Guard checks against, and the bounds it runs within when the Guard is itself a
Cog or a person — beside what the Guard adds.

```yaml
# guards/sensitive-data-guard.yaml
id: sensitive-data-guard
version: 0.0.1
name: Sensitive Data Guard

extends: organization-baseline:0.0.1  # the strictest Policy of the catalogue

category: policy-safety
stages:
  - in_flight
  - post_run
method: algorithmic

check: >-
  No output, tool argument or outbound message contains a credential or
  personal data.

signals:
  - name: sensitive_data_detected
    type: boolean
    description: Sensitive data was found where it must not be.

required: true
```

## Fields

| Field | Meaning |
| --- | --- |
| `id`, `version`, `name`, `description` | As on every spec. |
| `extends` | The Policy the Guard extends, `id` or `id:version`. Required; one of the catalogue. |
| `category` | Which of the seven categories it is. Required. |
| `stages` | The stages of an Op it may run at: `preflight`, `in_flight`, `post_run`, `continuous`. Required. |
| `method` | How the check is made: `algorithmic` (code), `cog` (a Cog judges), `human` (a person judges). |
| `check` | What is verified, written so that code, a Cog or a person can run it. Required. |
| `signals` | What it reports beside pass or fail — `name`, `type` (`boolean`, `number`, `string`) — for a Gate's condition to read. |
| `required` | Whether the work counts only once the Guard has passed. |
| `enabled` | Whether an Op may name it today. |

A Guard carries nothing of its Policy: a field of a Policy document written
on a Guard is refused.

## Categories and stages

| Category | What it verifies |
| --- | --- |
| `algorithmic` | An output against a deterministic rule or a known result. |
| `source-grounding` | Claims are supported by approved evidence. |
| `consensus` | Independent Cogs, prompts or models agree. |
| `expert` | A person judges sampled or high-risk outputs. |
| `policy-safety` | The work stays inside what is allowed. |
| `regression-drift` | An update has not changed behavior unacceptably. |
| `outcome` | The intended result is produced. |

| Stage | The question |
| --- | --- |
| `preflight` | Is this Op allowed and properly configured? |
| `in_flight` | Is the work staying within policy and expected bounds? |
| `post_run` | Is the output correct, useful, safe and ready for action? |
| `continuous` | Is quality improving, degrading or drifting over time? |

The Permission Guard checks the launching identity against the Policy's rules:
each class of action the Op's Cogs take is one the rules allow or ask about,
none is denied, and none needs an authorization the identity does not hold.

## Guards declared by a Frame

A [Frame](../frames) declares, inline, the checks its own context implies
(`totals-reconcile` on the Sales Pipeline Frame). They travel with the Frame
and reach an Op through its Cogs, as `frame_guards`. A Guard of this catalogue
is the reusable kind: it extends a Policy, reports signals, and is named by
an Op at a stage.

## In Python

```python
from agentspecs.guards import get_resolved_guard, guards_extending, policy_of

guard = get_resolved_guard("sensitive-data-guard")
guard["policy"]                         # 'organization-baseline:0.0.1'
policy_of(guard).policy["rules"]        # the Policy's rules, through the catalogue
[g.id for g in guards_extending("organization-baseline")]
```

A Guard that extends nothing, or something that is not a Policy of the
catalogue, names no stage or no check is refused when the catalogue loads.
